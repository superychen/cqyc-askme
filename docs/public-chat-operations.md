# 公开对话开发与运行说明

更新：2026-10-25。公开前台和问答后端已经实现；百炼 EnhancedSearch 已通过真实连接、工具发现及一次搜索验证，BGE 重排已部署并验证项目适配器。自我介绍问题已完成真实检索、事实审核和回答验证，完整浏览器链路与系统性阈值校准仍待完成。本文件区分本地验证与真实外部服务结果，不使用演示数据冒充上线效果。

## 1. 启动与入口

Docker 基础服务、重排、MinerU 以及四个应用终端的完整命令见 [本机全部服务启动命令](local-startup.md)。重排 Compose 位于 `deploy/reranker/compose.yaml`，固定模型版本、持久化权重缓存，仅向本机开放 7998 端口。

项目根目录同步 Python 依赖：

```powershell
uv sync --locked --extra rag
uv run --locked --extra rag uvicorn askme.main:app --reload --host 127.0.0.1 --port 8000
```

两个前端在不同终端运行：

```powershell
# 公开对话
cd front
npm ci
npm run dev
```

```powershell
# 管理后台
cd frontend
npm ci
npm run dev
```

- 公开前台：`http://127.0.0.1:5174/`，无需登录。
- 管理后台：`http://127.0.0.1:5173/admin/`；开发时前台的“管理入口”也代理到此服务。
- API：`http://127.0.0.1:8000/api/v1/chat`。
- 导入 Worker 的启动方式不变：`uv run --locked --extra rag python -m askme.worker`。

前台不展示虚构的个人履历；回答必须查实际知识库。历史不足不伪造数据，服务未配置时显示明确错误。

## 2. 必需配置

参考根目录 `.env.example`，只补充缺少的字段，不覆盖现有配置。

| 配置 | 说明 |
| --- | --- |
| `IP_ID_SECRET` | 独立的至少 32 字符随机密钥，本次已在本地 `.env` 缺失时生成，值没有输出；部署时沿用或在新环境安全生成 |
| `REDIS_URL` | 与现有管理端相同 Redis；生产启用持久化、备份及避免额度 key 被淘汰 |
| `DEEPSEEK_BASE_URL / MODEL / API_KEY` | 沿用现有模型配置，所有 LLM 调用走 LangChain |
| `RERANK_BASE_URL` | 指向提供 `/rerank` 的 Infinity 兼容服务，不能只配置现有 embedding 模型地址而不加载 reranker |
| `RERANK_MODEL` | `BAAI/bge-reranker-v2-m3` |
| `RERANK_API_KEY` | 重排服务若要求鉴权则填写，否则留空 |
| `RERANK_MIN_SCORE` | 调试初值 0.5，需用授权样本校准，不是“答案正确率”；全部低分时仍对有界候选做事实复核 |
| `BAILIAN_SEARCH_MCP_URL` | 百炼 EnhancedSearch 外部调用 URL；当前允许 HTTPS `dashscope.aliyuncs.com/api/v1/mcps/EnhancedSearch/mcp` |
| `BAILIAN_SEARCH_TOOL_NAME` | `search_pro`，已由真实 tools/list 确认；必填输入为 `query` |
| `DASHSCOPE_API_KEY` | 本地填写，不放前端、URL或聊天消息 |
| `WEB_SEARCH_BUDGET` | 本应用累计调用预算，默认 0 不外呼；部署者核对额度后启用 |

`IP_ID_SECRET` 不能随意轮换，否则同一 IP 会映射到新身份，历史无法关联且获得新额度。原始 IP 不写入普通日志；Redis 保存 HMAC 标识以及首次/最近访问时间。

百炼预算使用 Redis `askme:public:web_used`，预算预扣后不自动退回，因为超时可能已经产生费用。该预算看不到账号在其他项目的调用，不能保证账号整体不超出免费额度。变更预算配置前核对服务端计费设置。

当前 MCP 适配器严格校验 `query`、可选 `count` 输入及 `pages[{title,url,snippet}]` 输出。真实服务返回其他结构时，会标记 `WEB_PROTOCOL` 并降级到本地资料；必须依据真实工具 schema/脱敏返回样本补充适配，不能把异常当作“无搜索结果”。2026-10-22 已验证 EnhancedSearch 的 `search_pro` 仅需 `query`，不支持 `count` 参数；实际返回 `pages`，现有适配器成功保留前 5 条网页证据。

本地应用预算已设为 100。上述一次真实搜索计入 Redis 累计调用数，验证结束时已用 1 次；此记录不是账号免费额度或实时余额。修改 `.env` 后需重启后端进程，使缓存的 Settings 重新加载。

## 3. 代码阅读顺序

1. `front/src/useChat.ts`、`api.ts`：初始化、提问、SSE解析、澄清选择、停止和历史恢复。
2. `src/askme/api/routes/chat.py`：来源/身份/速率校验和公开接口。
3. `services/visitor.py`：可信来源 IP 规范化及 HMAC 身份。
4. `services/chat_store.py`：Lua CAS、20次永久额度、租约、幂等、历史、澄清续接。
5. `services/chat_service.py`：队列、流式发送、心跳、取消和崩溃回收。
6. `rag/chat_graph.py`：14节点图，以及每个节点的输入、输出和失败行为。
7. `integrations/llm.py / retrieval.py / enhanced_search.py`：模型、Milvus、重排和百炼 MCP 协议。

并行关系：`prepare_query → web_route → [rag_retrieve || web_search] → retrieval_join → fuse_candidates → rerank → evidence_gate`。RAG 必查；不需要联网时 Web 节点立即返回 skipped，不握手、不搜索。两路分别更新 `rag_*`、`web_*`，只有汇合节点写总状态。

同 IP 的多问题串行，但同一个问题的两路检索并行。默认全局最多 8 个活动生成，每 IP 每分钟最多 10 次提交（含失败提交）。同步 Milvus 调用最多 4 个实际在途线程，取消不会过早释放仍在运行的线程容量。

## 4. 状态、额度和恢复

- 一次问题的首个正文增量或三个选项，在 Redis 确认保存后计一次；多个 delta 不多扣。
- 首次输出之前失败/停止不扣永久额度，预占回收；输出后停止仍扣一次，内容标记 interrupted。
- 已计次的澄清选择继承原问题额度，第 20 个问题的有效选项仍能继续。
- 选择后仍无证据，明确不知道，不重复进入澄清循环。
- 只有输入辅助卡片时，点击只回填输入框，新输入仍按新问题处理。
- 同一 UUID、同一内容只恢复快照；同 UUID、不同内容返回 409。
- 首期不回放逐 token SSE；断线后查询请求状态恢复已保存内容，不自动重跑生成。
- 原始对话最多保留最近 60 个 turn（包含失败记录），有效历史最后一次对话后 30 天过期；永久计数和已扣次回执不设 TTL。
- 摘要使用旧摘要加新增完整轮次，最近 3 轮完整保留；摘要失败会在下轮尝试补偿，迟到摘要不能覆盖更新后的历史版本。
- API 后台每 15 秒回收失效租约，运行中每 3 秒续约/读取取消信号；单次操作总预算默认 120 秒。

运行依赖 Redis 正常工作；Redis 故障时不绕过额度继续生成。持久化与备份损坏可能导致永久计数丢失，应用代码不能替代数据库持久化保障。

## 5. 外部失败与事实边界

| 状态 | 行为 |
| --- | --- |
| RAG失败、集合不存在、向量维度不匹配 | 明确错误，中止回答，不用联网结果冒充履历 |
| RAG正常但没有结果 | 空结果澄清，不伪造证据 |
| Web未配置、预算不足、超时、协议不符 | 记录 failed，可用本地证据继续；时效问题不以旧资料冒充最新信息 |
| 重排未配置或结果索引/分值非法 | 明确错误，不拿COSINE分代替重排分 |
| 所有候选低于门槛 | 最多取 `ANSWER_CONTEXT_TOP_K` 条做事实复核；通过才回答，否则澄清或在续接后明确不知道 |
| 相关性高但个人事实没有依据 | 证据覆盖检查仍应拒绝确定性回答 |
| 模型正文中途断流/超长 | 保留已发布正文并标记未完成，不保存成正常完成 |

系统提示词包含原句：“如果不知道的东西一定不要胡乱编造，就回答不知道。”个人经历只用本轮 RAG 证据；网页仅用于一般技术解释。提示词和双重门控用于减少幻觉，不保证完全杜绝幻觉。

## 6. 生产部署

两个前端分别执行 `npm ci`、`npm run build`。生产 `/` 托管 `front/dist`，`/admin/` 托管 `frontend/dist`，`/api/` 转发后端。

示例配置见 `deploy/nginx-public-chat.conf.example`。启用 HTTPS 后设置原有 `COOKIE_SECURE=true`，将实际域名加入 `ALLOWED_ORIGINS`。Uvicorn 使用明确的可信代理范围，例如单层本机 Nginx：

```powershell
uv run --locked --extra rag uvicorn askme.main:app --host 127.0.0.1 --port 8000 --proxy-headers --forwarded-allow-ips 127.0.0.1
```

不要设置任意来源都可信；否则客户端可伪造 IP 绕过配额和读取其他 IP 的共享历史。多层代理/CDN 部署需要按实际链路配置可信来源，并由最外层清除客户端伪造头。

SSE 关闭反向代理缓冲/缓存及聚合压缩；读超时大于总操作预算。历史与状态接口 `Cache-Control: no-store`，不能被共享缓存。

### 2026-10-25 自我介绍误拒答排查与修复

当前三个已提交导入任务均为 `succeeded`，分块数分别为 10、8、40。介绍文档包含明确的姓名、自我介绍、工作经历和项目说明；无需重复上传来处理本次问题。

经用户明确授权，使用配置中的真实模型接口复现原问题“你叫什么名字，简单介绍下自己”：旧查询计划将它分类为 `other`，原样进入检索；20 条候选的前三个重排分数约为 0.04699、0.03234、0.02860，没有一条达到 0.5。旧门控在读取事实前就清空了候选，而澄清节点使用未过滤的召回结果，所以建议问题仍能提到个人资料。

修复后，查询计划明确“你”指知识库中的求职者，本次返回 `personal`。门控先限制个人资料来源；全部低分且候选非空时，按重排顺序最多复核 `ANSWER_CONTEXT_TOP_K` 条。审核仍必须确认正文依据并选出实际候选 ID，不直接把低分候选当成答案。事实审核同时接收原问题和独立检索问题，避免查询改写改变用户要求。

本次真实验证结果：相同问题与相同重排分数进入事实复核，返回 `answer`、4 条依据、无缺失项；回答正常包含姓名、后端经历、供应商 RAG 和中台多 Agent 项目。“你获得过诺贝尔奖吗？获奖年份是什么？”返回 `clarify`，明确没有获奖记录依据。验证直接调用查询、检索、门控与回答模型，未创建访客会话或消耗访客额度，也不等于完成了浏览器/SSE 全链路验收。

`python -m unittest discover -s tests -v` 的 10 项本地回归均通过，覆盖低分复核、缺失事实、个人来源限制、空结果、有界上下文、过线筛选、非法 ID、续接超时、时效失败和部分回答。测试使用演示文本及模拟审核结果，不能代替真实模型准确率评估；上面的真实调用只覆盖两个问题。全量阈值校准及浏览器验收仍待完成。

诊断日志 `Evidence gate reviewing` 仅记录筛选模式、候选数量和阈值；`low_score_review` 表示进入低分复核，`Evidence gate completed` 显示最终路由与支持片段数。日志不包含问题、姓名或文档正文。运行中的 API 如未启用热重载，更新代码后需要重启以生效。
