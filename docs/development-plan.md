# 个人 RAG 知识库问答系统：初步开发计划

## 1. 背景与目标

项目服务于个人求职场景，使用本人授权提供的简历、项目经历和其他资料构建知识库，让 Boss 直聘 HR 或 Agent 开发者通过问答了解求职者。

首期目标是可通过 Web 访问的个人知识库问答系统。这里的“蒸馏自己”按基于资料的 RAG 理解，当前没有模型训练或微调计划。暂不接入 Boss 直聘平台，也不实现自动投递或自动沟通。

## 2. 已确定范围

| 项目 | 当前约定 |
| --- | --- |
| 后端语言与接口 | Python、FastAPI |
| Python 环境与依赖管理 | 统一使用 uv，启动使用 `uv run uvicorn` |
| RAG 与流程编排 | LangChain、LangGraph |
| 向量数据库 | Milvus |
| 大语言模型 | DeepSeek Flash，配置名预留为 `deepseek-flash` |
| 缓存 | Redis |
| PDF 转 Markdown | MinerU |
| 图片理解与存储 | DeepSeek Flash 图片输入、MinIO 读写 |
| Embedding | BGE-M3，调用本地自部署服务，后续迁移到阿里云服务器 |
| Markdown 产物 | 项目根目录的 `docs/pdfToMd/` |
| 前端 | Vue，具体版本与配套方案后续讨论 |
| 管理后台 | 管理员登录，单管理员账号配置在环境变量中 |
| 文档格式 | 只支持 PDF 和 Markdown（`.pdf`、`.md`） |
| 前台访问 | 公开问答，不要求访客登录 |
| 提问额度 | 每名匿名访客最多 20 个问题；识别方式和计数周期待定 |

## 3. 本次交付与边界

初始阶段完成 Python 工程骨架及本计划书。当前管理员登录和知识库导入代码、Vue 页面已实现，外部服务待用户云端部署后联调。模块方案见 [技术方案](admin-import-design.md)，启动和接入见 [运行说明](admin-import-operations.md)。Python 3.11 为当前开发基线。

本次交付包含项目元数据和依赖声明、FastAPI 入口与统一路由、环境配置、启动/停止日志、进程存活接口、后续模块空目录和启动说明。基础依赖与可选 RAG 集成依赖分开声明。

初始骨架阶段不实现业务功能的限制已随用户授权开发而更新：本阶段实现管理员认证、上传/解析适配、分块/向量化、Milvus 写入及 Vue 管理页。检索生成、匿名额度和外部服务部署仍不在本阶段范围。按用户最新要求不创建测试用例，不导入真实个人资料或调用真实模型。

## 4. 初步结构与职责

```text
Vue 管理端 → FastAPI 管理接口 → 文档导入流程
                                  PDF → MinerU → Markdown
                                  Markdown → 统一处理
                                  → 分块 → Embedding → Milvus

Vue 问答端 → FastAPI 公开接口 → 匿名额度校验（Redis，具体方案待定）
                              → LangGraph 问答流程
                              → LangChain 检索组件 → Milvus
                              → DeepSeek Flash → 回答与资料引用
```

以上是讨论用流程，不代表已经实现或固定了详细设计。

| 模块 | 后续职责 |
| --- | --- |
| `api` | 区分管理员与公开接口，处理请求和响应 |
| `core` | 环境配置、日志等公共基础设施 |
| `schemas` | 接口输入输出的数据模型 |
| `services` | 管理员认证、文档导入和问答业务协调 |
| `integrations` | DeepSeek、Milvus、Redis、MinerU 访问封装 |
| `rag` | 文档处理、检索与 LangGraph 流程 |

已确认图片使用 MinIO、Markdown 产物保存到 `docs/pdfToMd/`，MinerU 与 BGE-M3 通过独立自部署服务接入。任务状态、原文件及其他产物的存储与恢复建议见模块技术方案；首版建议不新增关系数据库。

## 5. 分阶段计划

| 阶段 | 主要工作 | 完成标准 |
| --- | --- | --- |
| 0：本次骨架 | Python 包结构、依赖声明、配置、FastAPI、文档 | 不依赖外部服务即可启动，提供进程存活接口；业务模块保持预留 |
| 1：需求与方案确认 | 确认匿名额度、Embedding、文档存储、MinerU 接入方式、部署与隐私范围 | 形成双方认可的详细设计，再进入业务开发 |
| 2：后台与文档导入 | 管理员认证、PDF/MD 上传、格式与大小校验、解析、导入状态 | 管理员可查看导入结果；未登录不能导入；失败可定位原因 |
| 3：知识库构建 | Markdown 处理、分块、Embedding、Milvus 写入、来源元数据 | 已导入资料可检索，结果能够追溯到原始资料 |
| 4：公开问答 | LangGraph 编排、检索、DeepSeek 生成、资料引用、匿名 20 次额度 | 可据资料回答；资料不足时明确说明；额度耗尽后阻止继续问答 |
| 5：Vue 页面 | 管理员登录/导入页、公开问答页、剩余次数及错误反馈 | 两条业务流程可以从浏览器完成 |
| 6：联调与交付 | 经确认后编写测试、联调异常路径、部署配置、使用说明 | 关键流程及额度边界通过约定验证，具备可运行交付说明 |

以上仅表示工作顺序，不承诺工期；细节确认后再拆分任务并估时。创建或修改任何测试用例前，必须先征得用户确认。

## 6. 下一轮需要讨论的问题

### 6.1 匿名访客如何限定 20 个问题

尚未决定匿名访客标识、额度重置周期，以及失败请求是否计数。Cookie/匿名令牌可标记浏览器，但用户清除 Cookie 后可能重新获得身份；IP 标识可能误伤共享网络中的不同访客。上线前需要明确可接受的限制强度。

后续实现需在服务端校验额度，并设计 Redis 原子计数、并发请求处理、失败回滚与过期策略，避免并发绕过上限。Redis 故障时如何处理公开问答也需约定。

### 6.2 Embedding 与检索策略

DeepSeek Flash 作为回答和图片理解模型；文档向量化已确认使用本地部署的 BGE-M3 服务，首版建议使用其 1024 维稠密向量。导入切分按标题分节、长节递归切分、短节贪心合并设计，详见模块方案。公开问答的召回数量、是否重排以及资料不足的判断方式仍待后续设计。

### 6.3 文档生命周期

已确认 MinerU 自部署，PDF 转换结果保存到 `docs/pdfToMd/`、图片读写 MinIO。模块方案提出异步导入、实时进度、文件大小限制、去重及恢复的建议默认值；更新/删除暂不纳入首版建议范围。MinerU 的实际服务协议、运行资源和解析能力在接入阶段验证。

### 6.4 回答与个人信息边界

确认哪些资料可以公开、回答风格、是否支持多轮上下文和流式输出，以及资料引用的展现形式。建议默认只根据授权公开资料回答，不编造经历；上传资料中的指令应作为资料内容处理，不能覆盖系统规则。问答记录是否保存及保存周期待确认。

### 6.5 管理与部署

确认管理员会话方式、有效期、生产环境的 API 文档访问策略，以及服务部署位置、域名和 HTTPS。管理员凭据与模型密钥仅从环境配置读取；后续日志需要包含任务/请求标识、步骤和失败原因，但不得记录密码、令牌、密钥或个人敏感信息。

## 7. 后续验证方向（待授权后落地）

- 认证：未登录不能上传，失效会话不能访问管理接口。
- 导入：PDF/MD 成功路径、非法文件、空文件、超限、解析失败和重复导入。
- 知识库：入库资料可召回，答案引用可追溯，无资料依据时不编造经历。
- 额度：第 20 个问题允许，第 21 个被拒绝；并发下上限仍生效。
- 故障：模型、解析服务、向量库和 Redis 不可用时，返回可理解的错误并留下可定位且脱敏的日志。

这些是后续验收方向，当前没有创建测试文件或实现测试用例。

## 8. 依赖与参考

Python 环境、依赖安装、依赖增删和项目命令执行统一使用 uv；Uvicorn 保留为 FastAPI 的 ASGI 服务器。使用 `uv add` / `uv remove` 管理依赖，`uv sync` 同步环境，`uv run uvicorn askme.main:app` 启动应用。RAG 集成阶段使用 `uv sync --extra rag`，启动时同样携带 `uv run --extra rag`。

依赖声明保存在 `pyproject.toml`，精确版本由 uv 生成的 `uv.lock` 管理并提交版本控制，不手动修改锁文件。首次同步生成锁文件后，使用 `uv sync --locked` 校验并复现环境。

当前已通过 uv 使用 Python 3.11.17，在项目独立 `.venv` 中安装基础依赖和 RAG 可选依赖，并生成 `uv.lock`；未向全局 Python 安装项目依赖。项目专用解释器及下载缓存放在已忽略的 `.uv/` 下。复现完整环境使用 `uv sync --locked --extra rag`。

当前只完成依赖安装，尚未连接外部服务。集成阶段继续确认 LangChain/LangGraph、Milvus 服务端与 PyMilvus、MinerU 的兼容性，验证后再确定部署版本。
